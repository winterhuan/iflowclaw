# iFlowClaw 记忆系统现状与规划

## 现状

当前仓库里还没有独立的“长期记忆数据库”实现。

目前真正生效的上下文机制主要有三类：

### 1. 群组 AGENTS

来源：

- `groups/<folder>/AGENTS.md`
- `groups/global/AGENTS.md`

作用：

- 作为系统提示词的一部分注入
- 适合放稳定规则、团队约定、长期背景信息

### 2. 会话续用

会话 ID 会按 `group_folder` 保存在数据库里。

作用：

- 后端支持时，后续消息可复用之前的会话状态
- 这是当前最接近“短中期记忆”的机制

### 3. skills

来源：

- 项目级 `skills/`

作用：

- 给后端补充结构化能力说明
- 通过模板变量把群组目录、全局目录、IPC 路径等注入 skill 文档

## 当前局限

与真正的记忆系统相比，现状有几个明显限制：

- 没有独立的 memory table
- 没有结构化记忆写入与检索 API
- 没有跨会话摘要生成
- 没有显式“保存偏好 / 决策 / 待办”的工具
- 主要依赖 `AGENTS.md` 和会话上下文维持长期信息

这意味着：

- 稳定背景信息适合放文档
- 临时连续对话适合靠 session 续用
- 复杂长期记忆目前还没有正式主链路

## 为什么暂时这样设计

当前项目优先级仍是：

- 跑通多后端
- 跑通群组隔离
- 跑通任务调度
- 跑通 MCP 工具桥

在这个阶段，先用 `AGENTS.md + session_id + skills` 组成“轻量记忆层”是符合项目复杂度目标的。

## 适合当前系统的记忆分层

### 稳定规则层

适合放在 `AGENTS.md`：

- 回复风格
- 团队信息
- 长期流程约定
- 项目固定背景

### 能力说明层

适合放在 `skills/`：

- 固定命令说明
- 调查步骤
- 面向特定任务的操作手册

### 短期上下文层

适合由后端 session 续用承担：

- 最近一段会话的连续状态
- 当前任务上下文

## 后续规划方向

如果要做正式记忆系统，建议沿以下方向逐步推进：

### 第一阶段

先补最小可用记忆：

- 新增 `memories` 表
- 新增 MCP 工具：`save_memory`、`search_memory`、`list_memories`、`delete_memory`
- 只支持按群组存储，不做向量检索

### 第二阶段

再补自动摘要：

- 长会话摘要
- 任务执行摘要
- 会话切换摘要

### 第三阶段

最后再考虑更复杂能力：

- 重要性评分
- 过期策略
- 语义检索
- 不同后端之间的统一记忆注入策略

## 当前建议

在正式记忆系统落地前，推荐做法是：

- 把长期规则写进 `groups/<folder>/AGENTS.md`
- 把跨群共享规则写进 `groups/global/AGENTS.md`
- 把高频操作说明写进 `skills/`
- 不要把“记忆系统已实现”当成当前事实
